# Kaggle notebooks

GPU-heavy stages (adapt, draft training, larger acceptance audits, vLLM benchmarks) run on Kaggle.

Rules:

- Notebooks install this package and call library functions. No logic lives only in a notebook.
  ```python
  !pip install -q "git+https://github.com/<user>/zubaan.git#egg=zubaan[train]"
  ```
- Set the accelerator to GPU T4 x2 or P100 and turn internet on.
- Store `HF_TOKEN` as a Kaggle secret, never in code.
- T4 and P100: use fp16 (no BF16, no FP8).
- Push checkpoints to the Hugging Face Hub during training and resume with `resume_from_checkpoint=True`.
- Run long jobs as background commits (Save Version, Save and Run All).

Naming: `NN_stage_purpose.ipynb`, for example `05_adapt_qwen3_1.7b.ipynb`.

Existing notebooks: `01_audit_acceptance_qwen3.ipynb` (stage 1 acceptance) and `02_extend_quality_qwen3.ipynb` (stage 2 quality run, about 2 hours on a T4; generated by `make_02_notebook.py`). `03_extend_export_qwen3.ipynb` (stage 2 deliverable for Qwen3-1.7B, generated by `make_03_notebook.py`) runs on a **CPU** session, needs about 12 GB RAM and 20 GB disk, and takes about 1 hour. It installs zubaan from one pinned commit, so push that commit to GitHub before running it. `04_vllm_check_qwen3.ipynb` (generated by `make_04_notebook.py`) starts vLLM on the extended model from the finished 03 output (add it with *Add Input > Notebooks*). It needs a **GPU T4**: vLLM requires compute capability 7.0 or higher and the P100 is 6.0. vLLM is installed into its own Python 3.12 environment so it cannot replace Kaggle's torch. It prefers this notebook over the optional vLLM cell at the end of 03, which needs the whole 03 pipeline in the same session. Regenerate with `python notebooks/make_03_notebook.py` (it pins the current git HEAD) whenever the code changes.

`05_adapt_qwen3.ipynb` (stage 3, generated by `make_05_notebook.py`) trains the extended model on a **GPU** (one T4 is used). Set `MODE` to `check`, then `smoke`, then `main`: five fp16 steps, a 30-step run that is killed and resumed (it reports tokens per second, peak memory and the projected hours), then the full run with merge and save. Add the finished output of notebook 03 as an input, set `HUB_REPO` to a **private** repo and store `HF_TOKEN` as a secret to make long runs resumable. It installs zubaan from one pinned commit, so push that commit first, then regenerate with `python notebooks/make_05_notebook.py`.
